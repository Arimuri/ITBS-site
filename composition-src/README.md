# 応用実習1,2：作曲 特設サイト（composition-site）

公開URL：https://intheblueshirt.com/composition/

`curriculum.md` を唯一の原稿として、`../composition-site/` に静的HTMLを書き出す。

## 更新のしかた

1. `composition-src/curriculum.md` を直す（ここが唯一の正本）
2. `python3 composition-src/build.py`
3. コミットして main にpush（GitHub Actionsでさくらサーバーへデプロイ）

授業の条件と、設計をなぜそうしたかの経緯は `CLAUDE.md` にある。
解禁音の順番や回の構成を変えるときは、先にそちらを読むこと。

## 見た目について決めたこと

- 背景は薄い水色（`--page:#e6f4fc`）。**OSのダークモードでも反転させない**。
  授業で投影すること、学生の端末がまちまちなことを優先し、`prefers-color-scheme` の分岐は置いていない
- 色は全てCSS変数で持つ。色地に文字を載せるときは `--acc` ではなく `--acc-ink`
  （`--acc` を `--acc-soft` の上に置くとコントラストが 4.04:1 で基準を割るため）
- `tips/`（ポップスのコツ）と `roadmap/`（理論ロードマップ）は
  **授業から独立して読める資料**として組む。
  コツ本文を主役にし、「ドリルNで習う」は各項目の末尾に小さく添えるだけにする

## 和音のボイシング

サイトで鳴る和音（コードtier・ピアノロールの伴奏・段階4の鍵盤・1度当て）は全部 `assets/voicing.js` を通す。
1度当て（手書き）も `../assets/voicing.js` を読んでいる。

- ベースはルート（分数コードは分母）を C2〜D#3 に置き、鳴らす側でオクターブ上も半分の音量で重ねる。
  音色がほぼ正弦波なので、低音だけだとノートPCやプロジェクターのスピーカーではルートが聞こえず、
  ルート抜きの4和音が別のコードに聞こえる（Cキーの IIm7 と IV は上の3声が同じ A3 C4 F4）
- 上の3声は密集の転回形で F3〜A#4 に収める。4和音はルートをベースに任せ、上は3・5・7
- 上の一番下はベースから5度以上離す。重ねたオクターブと半音でぶつかる配置は選ばない
- 単独の和音は真ん中（C#4 あたり）に寄せる
- 進行のつなぎは、ループの継ぎ目も含めてコストの合計が最小になる組み合わせを選ぶ。コストは
  **有村さんの Emocute Studio の chord_gen（`_vl_pair_cost`）を移植した簡易版**
  （原典：`~/Dropbox/Emocute Studio/Emocute Studio v8/emocute/voicing.py`）：
  - 共通音の保持ボーナス／移動距離の段階コスト（順次は安く、跳躍ほど高い）
  - トップノートの旋律化（保持・順次にボーナス、5半音以上の跳躍にペナルティ）
  - ガイドトーン（3rd・7th、susの4thと6thは代理）の連結ボーナス。4度・5度進行の 3rd↔7th 交換が最強
  - 並行5度・8度ペナルティ（ベース込み、外声は重め）／外声の反行ボーナス
  - ベースとの短9度・上3声の半音密集はソフトペナルティ（従来の禁止ルールも残す）
  - 単独の和音（tier表・鍵盤）はつなぎが無いので従来と同じ音になる
- ピアノロールは、Cキーで組んだ伴奏をメロと同じ量（`keyOffset`）平行移動する。キーごとに組み直すと
  転回形が変わって、メロと伴奏の距離がキーでずれるため
- スケール鍵盤（段階3）は和音を鳴らさない。押した音だけ鳴る（主和音を重ねると別の和音に聞こえて分かりにくいため、2026-09-29）
- コードtierは同時に1和音だけ鳴らす。次を押すと前の和音は30msで消す

## 4小節ピアノロールについて

各回のページの「4小節つくってみる」。`<div class="roll" data-lesson data-prog data-degrees>` を
`assets/roll.js` が中身で埋める。

- 行は半音ごと（2オクターブ25行）、横は8分音符32マス＝4小節
- 再生中に置いた音は、**その周のうちに鳴る**。8分音符ごとに `SCHED_AHEAD`（0.12秒）だけ先を
  予約する方式にしてあるため。1周ぶんをまとめて予約すると、置いてから最大1周（100BPMで9.6秒）
  待たされるので戻さないこと。予約の直前に打ち込み内容を読むので、消した音もその周から消える
- テンポは70〜140BPMのプルダウン（既定100）。鳴らしている最中に変えると、その場で切り替わる。
  選択肢を増やすなら build.py の `BPMS`、既定を変えるなら `DEFAULT_BPM`
- プルダウンで選んだキーのメジャースケールの行だけ色が濃くなり、1〜7の番号が振られる
- その回までに解禁された度数（今回使う音）の行は黄色、番号も強調される（`data-degrees`）。見本ロール（roll-demo）は解禁なし
- コード進行はプルダウンで差し替えられる。候補は build.py の `ROLL_PROG_CHOICES`
  （右の数字＝その進行を出してよい最初のドリル。解禁順を変えたらここも直す）
- **移調は、メロ全体と伴奏を必ず同じ量だけ動かす。** ここは壊しやすいので触るときは注意:
  - 音を1つずつオクターブ折り返しするとメロの形が壊れ、同じマスに重なった音が消え、キーを戻しても戻らない
  - 伴奏の基準音を `LOW + tonicPc`（0〜+11）にすると、伴奏だけ最大1オクターブ上がってメロが埋もれる。
    `keyOffset()` で±6に正規化し、メロの移動量と必ず揃えること
  - 盤面に収まらないときは、まずオクターブ単位でまとめてずらす。それでも無理なら動かさずに警告を出す
- キーを変えるとメロも一緒に移調する（既定ON）。第2限の「移調しても数字は同じ」の確認に使える。
  チェックを外すと移調せず、同じ高さのまま度数だけが変わる
- 打ち込み・キー・テンポは各回ごとにブラウザに保存される（localStorage `roll:01`〜`roll:15`）。
  端末を変えると消えるので、提出物には使えない

**コード進行の決まりかた**

原稿の「伴奏進行」からローマ数字の並びを拾う。拾えた数が4に満たないときは繰り返して4小節にする。
「自由」「V7を多用」など拾えない回は、build.py の `FALLBACK_PROGS` の既定値を使う。
授業に合わせて変えたいときはここを直す。

| ドリル | 既定の進行 | 出どころ |
| --- | --- | --- |
| 1・2 | IVM7-IIIm7-IIm7-I | 原稿の伴奏をそのまま |
| 3 | I-VIm-IV-V | 原稿の伴奏をそのまま |
| 8 | IV-I-IV-I | 原稿の「IV中心（IV-I…）」から2つ拾って繰り返し |
| 11 | I-VI7-IIm7-V | 原稿の伴奏をそのまま |
| 13 | I-IV-♭VIM7-♭VII7 | 原稿の伴奏をそのまま |
| 4〜7・9・10・12・14・15 | I-VIm-IV-V ほか | `FALLBACK_PROGS` の既定値（ドリル12だけ IV/V 入り） |

臨時記号（#・♭）、M7、dim7 も拾える。`m7-5` は区切りの `-` とぶつかるので、進行には書かない。

## 原稿の書式（build.py が読んでいるところ）

- `## 授業の狙いと前提` の `**到達目標**` の塊は、トップの一番上（リード文の下）に出る。残り（表記ルールなど）は下の方
- `## 全14回一覧` の表：`ドリル / 授業 / Phase / テーマ / 使える音 / 伴奏進行` の列名で引いている。
  `授業` はそのドリルをやる授業の回（ドリル1・2はどちらも1）。カードとドリルのページ上部に出る。
  トップのカードの下の「全14回の予定」（授業｜ドリル｜Phase｜テーマ｜新コード）も、この列と各ドリルの「新コード」行から作る
- その下に空行をはさんで `| 授業 | 日付 | 予定 |` の表を置く。日付はカード・ドリルのページ・予定表に出て、予定（例：3Q末課題）はその回に付く。
  授業が `—` の行は授業のない日（補講日など）として予定表に日付順で出る。3Q／4Q の区切りは build.py の `QUARTERS`
- `使える音` は累積で解釈する。`＋4` は前回までの音に4を足す、`全7音`・`全て` も解釈する
- `## 各回の詳細` の `### Phase …` → `#### ドリルN　テーマ` → `- **狙い**：…` の3階層
- `#### ドリルN` 直下の `- **ラベル**：本文` がそのまま各回ページの行になる。ラベルは自由に増やせる
- **授業の流れ**：`#### ドリルN` の中に `##### 見出し` を並べると、その順に番号付きの大きい節として
  ページの一番上（h1 の直下）に出る。投影して上からスクロールで授業を進めるため。
  設計メモの行（`- **ラベル**：本文`）は「このドリルの設計」として流れの下に回る。`#####` より下の行はメモに拾われない
  - `{{roll}}`：その位置に練習用の4小節ロールを置く（右カラムのロールは出なくなる）
  - `{{roll-demo C4:0-1 B3:2-3 D4:18 …}}`：見本のメロを置いたロール。`prog=I-I-I-V7` で伴奏、`bars=9` で小節数、`key=5` で最初のキー（0=C）。進行の1小節は `I+IV` で真ん中で切り替え、`NC` でコードなし（弱起の小節）。同じ高さの音を続けて書けば別々の音として鳴る。`音名オクターブ:マス` でマスは8分音符・0始まり、
    `0-1` は両端を含む範囲。進行はそのドリルの伴奏。保存しないので、いじっても開き直せば見本に戻る
  - `{{progmini}}`：簡易コード進行ジェネレータ（4小節をダイアトニック7つからプルダウンで選んでループ、キー選択、1度を鳴らす）。
    中身は `assets/keyboard.js`
  - `{{from-roadmap 段階3}}`：ロードマップのその段階の鍵盤と表だけを引用（表の原稿はロードマップ側の1か所のまま）
  - 流れに鍵盤系の部品があるページだけ `keyboard.js` を読む
  - 2026-09-30 に全ドリルを流れの形式にそろえた。ドリル2〜15は旧来の行を機械的に移した：
    狙い＋講義→「今日覚える」、新コード→「新コード」、分析→「例を聴く」、基本・発展課題→「やってみる」＋`{{roll}}`、
    制作回（6・14）は「課題」、15は「形式」「振り返り」。時間配分は削除
  - 流れがあるページは右カラムのロールを出さない。`- **ラベル**：本文` の行として残すのは
    伴奏（ロールの進行の元）・新コード（トップのカード用。ページには流れの節で出す）・フォロー（教員メモ）だけ
- `- **新コード**：IVm7（tier2）。…` と書くと、最初の「（」か「。」の手前までがトップのカードに「新コード」として出る
- `## ポップスのコツ` の表：`導入ドリル` 列の数字から、各回ページの「この回で教えるコツ」を作る
- `## ポップスのコツ` の、冒頭文と表の間に `**観点：見出し**` の塊を置くと、その観点の節ごとページの一番上に出る（例：`**コード：覚えるべきコード**` と tier 表）
- 冒頭文のすぐ下に `**鉄則**` と1段落を置くと、ページ全体の鉄則として一番上に大きく出る
- 表の後ろに `**観点：鉄則**` と1段落を置くと、その観点の節の頭に大きく出る
- `{{interval}}` `{{scale}}` `{{diatonic}}` `{{chords}}` だけの行は鍵盤・コード表の置き場になる（`assets/keyboard.js` が中身を作る）
- `## ざっくり音楽理論史` の節（見出しに「理論史」が入っていればよい）：`### 系譜名` の下の
  `- **年代　見出し**：本文` が年表の1ノード（ノード＋カード）になる。ラベルの頭（全角空白の前）が
  年代・数字ならその節は年表、そうでない節（つながりの節）は定義行で出る。
  年表は kammerkonzert/ensemble/ の振り子年表の簡易版：縦＝時間、クラシックは左トラック、
  見出しに「バークリー」が入る系譜は右トラック（緑）。折れ線が全ノードを時系列につなぐ。
  **年表でない節の「この授業」の行は、年表の最後に中央の合流ノードとして出る**（定義行には出ない）。
  それ以外の行がその節にあれば、年表の下に定義行で出る。節ごと消せばページも消える

列名や見出しを変えると build.py が止まる（どの節が見つからないか表示される）。
